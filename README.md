## What It Does

When a Jenkins pipeline fails, most teams spend **20–40 minutes** digging through raw logs to find the root cause. This agent does it in seconds.

The moment a build fails, the agent:

1. **Captures** the exact failed stage logs automatically
2. **Sends** them to GPT-4o with a structured prompt
3. **Parses** the AI response into structured fields (category, severity, failure type, root cause, fix, playbook, prevention)
4. **Detects** if the failure is a recurring pattern using a SHA-256 fingerprint
5. **Stores** the incident in SQLite with full metadata
6. **Emails** an enriched RCA alert to the right team (Docker → DevOps, npm → App Team, etc.)
7. **Displays** everything on a live dashboard

## Quick Start

### Prerequisites

- Python 3.10+
- Jenkins (local or remote)
- OpenAI API key
- Docker (for the pipeline stages)

---

### Step 1 — Clone the Repository

```bash
git clone https://github.com/harishkumar04/Jenkins-RCA-Agent.git
cd Jenkins-RCA-Agent
```

---

### Step 2 — Choose Your Edition

This repo has two editions. Use the **Value Edition** for the full feature set.

| Edition | Path | Features |
|---|---|---|
| **Core** | `/` | Basic RCA, email alerts, SQLite |
| **Value Edition** ⭐ | `/jenkins-ai-agent-value-edition/` | + Fingerprinting, recurrence memory, code context, insights API, advanced dashboard |

```bash
# For the Value Edition (recommended)
cd jenkins-ai-agent-value-edition
```

---

### Step 3 — Create a Virtual Environment

```bash
python3 -m venv .venv
source .venv/bin/activate      # macOS / Linux
# .venv\Scripts\activate       # Windows
```

---

### Step 4 — Install Dependencies

```bash
pip install -r requirements.txt
```

---

### Step 5 — Configure Environment Variables

```bash
cp .env.example .env
```

Open `.env` and fill in your values:

```env
# Required
OPENAI_API_KEY=sk-...

# Email Alerts (optional but recommended)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=you@gmail.com
SMTP_PASSWORD=your_app_password
SMTP_FROM=you@gmail.com
SMTP_TO=team@yourcompany.com
SMTP_USE_TLS=true

# Owner Routing (optional)
OWNER_DOCKER=DevOps Team
OWNER_EMAIL_DOCKER=devops@yourcompany.com
OWNER_NPM=Application Team
OWNER_EMAIL_NPM=app-team@yourcompany.com
OWNER_SECURITY=Security Team
OWNER_EMAIL_SECURITY=security@yourcompany.com

# Code Context (optional)
ENABLE_CODE_CONTEXT=false
APP_READONLY_DIR=/path/to/your/app
```

> **Gmail tip:** Use an [App Password](https://support.google.com/accounts/answer/185833), not your account password.

---

### Step 6 — Start the Backend

```bash
uvicorn main:app --host 127.0.0.1 --port 8000
```

Verify it's running:

```bash
curl http://127.0.0.1:8000/health
# {"status": "ok"}
```

---

### Step 7 — Open the Dashboard

```bash
open index.html
```

The dashboard connects to `http://127.0.0.1:8000` and shows all incidents in real time.

---

### Step 8 — Wire Up Jenkins

In Jenkins, create a new Pipeline job and point it to the `Jenkinsfile` in this repository.

Add your Docker Hub credentials to Jenkins Credentials Store with the ID:

```
dockerhub-creds
```

The `Jenkinsfile` automatically:
- Logs every stage to `pipeline.log`
- On any failure, extracts the failing stage logs
- POSTs them to the RCA backend
- Prints the AI analysis in the Jenkins console

## How Recurring Detection Works

Every incident gets a **stable SHA-256 fingerprint** based on its category and failure type (noise words removed). When a new failure comes in:

1. The fingerprint is computed
2. SQLite is queried for matching fingerprints
3. If matches exist, `recurring = Yes` and previous build URLs are attached
4. The AI prompt is enriched with the prior fix history

This means the second time Docker daemon fails, you immediately see: *"This happened in Build #34 and #41. The previous fix was: restart Docker daemon."*

## Security Notes

- The backend uses **read-only** access to your app source (when `ENABLE_CODE_CONTEXT=true`)
- Ignored directories: `node_modules`, `.git`, `dist`, `build`, `coverage`, `.next`
- Only allowlisted file types are read: `.js`, `.ts`, `.json`, `.yml`, `.yaml`, `.dockerfile`, `Dockerfile`, `Jenkinsfile`
- No writes are made to the app directory, ever
- Use HTTPS and restrict `allow_origins` in `CORSMiddleware` in production
